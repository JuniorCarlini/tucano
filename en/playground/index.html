Playground

Pick a component, change its options and see the result right away. The code below follows every change: HTML with data-* attributes, JavaScript and, where it makes sense, a Django template.

Events

Every callback call shows up here, with the arguments it received.

    Code

    Only the options you changed are included: what stays at the default does not need to be written. An option marked JS has no data-* attribute and only shows up in JavaScript.

    Where the options come from

    The form is not written by hand. At build time, tools/site.mjs reads every option from the same inventory that generates the API table and llms.txt: name, default, accepted values and the data-* attribute read by auto-initialization. An option renamed in the code breaks the build, instead of leaving a control here that does nothing.

    What does not fit a control is left out — functions, arrays and objects. Callbacks become the event list next to the preview, and the full reference for each component is still in the API section of its page. The option notes come from comments in the source code, which are written in Portuguese, so they only show on the Portuguese page.
