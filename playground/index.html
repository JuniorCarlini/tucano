Playground

Escolha um componente, mude as opções e veja o resultado na hora. O código embaixo acompanha cada troca: em HTML com atributos data-*, em JavaScript e, quando faz sentido, no template do Django.

Eventos

Cada callback chamado aparece aqui, com os argumentos que recebeu.

    Código

    Só entram as opções que você mudou: o que ficou no padrão não precisa ser escrito. Opção marcada com JS não tem atributo data-* e aparece só no JavaScript.

    De onde vêm as opções

    O formulário não é escrito à mão. No build, o tools/site.mjs lê cada opção do mesmo inventário que gera a tabela de API e o llms.txt: nome, padrão, valores aceitos e o atributo data-* que a inicialização automática lê. Uma opção renomeada no código quebra o build, em vez de deixar aqui um controle que não faz nada.

    Ficam de fora o que não cabe num controle — funções, listas e objetos. Os callbacks viram a lista de eventos ao lado da prévia, e a referência completa de cada componente continua na seção API da página dele.
