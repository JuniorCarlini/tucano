    Where the options come from
    

    The form is not written by hand. At build time, tools/site.mjs reads every option from the same inventory
   that generates the API table and llms.txt: name, default, accepted values and the data-*
   attribute read by auto-initialization. An option renamed in the code breaks the build, instead of leaving a control
   here that does nothing.
    

    What does not fit a control is left out — functions, arrays and objects. Callbacks become the event list next to the
   preview, and the full reference for each component is still in the API section of its page. The option notes come
   from comments in the source code, which are written in Portuguese, so they only show on the Portuguese page.
