How to use

Indicator only, one step per page

An <ol> with each step's name. The template marks the current one with aria-current="step", which the screen reader announces as "current step", and the previous ones with is-done. There's no script: it's the path for django-formtools' SessionWizardView, or any wizard where each step is a POST.

    
  {% for step in wizard.steps.all %}
    
  1. 
      {{ step|title }}
    
    2. 
  {% endfor %}

Wizard on a single page

The indicator, one .tuc-stepper__panel per step — with hidden from the second one on — and the button bar. Steps and panels match by order. The panel's title (an <h2> to <h6>, or the <legend> of a <fieldset>) gets focus on every change, and the screen reader announces the new step.

Continue checks the step's fields with the browser's own validation — required, type="email", pattern, min — and doesn't move on if any fails: the field gets aria-invalid="true" and the browser's message. Back never checks. On the first step Back goes away, and on the last one Continue gives way to Finish. The hidden on those two in the template is what makes the bar right before the script runs.

Why it's a single form

A hidden panel doesn't leave the DOM, so every name goes in the final POST, and the server receives exactly what it would from one long form. There's no JavaScript state to keep in sync, and server-side validation stays the same.

Enter in a text field, before the last step, is Continue. Without that it would submit the form, and the browser would block the submission over a required field the person hasn't even seen yet, without saying which. A reset on the form goes back to the first step.

With Django, when the server returns an error

A form that comes back from the POST with an error opens straight on the step of the first field with aria-invalid="true" — which Django 5 writes on its own on every field that failed. Without that, the message would be hidden two steps ahead.


  Address
  {{ form.zip }}        {# with an error, it comes with aria-invalid="true": the wizard opens here #}
  {{ form.zip.errors }}

To open on a chosen step, use data-start="2" (counting from zero). Without it and without errors, the step marked with aria-current="step" wins, or the first one. data-validate="false" lets the person move on without checking.

In JavaScript

const wizard = new Tucano.Stepper('#signup', {
  start: 0,          // initial step
  validate: true,    // Continue checks the step's fields
  onChange: (index, { panel }) => console.log(index, panel),
});

wizard.next();                   // checks and moves on
wizard.prev();                   // goes back, without checking
wizard.go(2);                    // jumps straight there, without checking
wizard.go(0, { silent: true });  // without firing onChange
wizard.checkStep();              // true if the step's fields pass
wizard.index;                    // open step

Every change fires tucano:change on the wizard element, and the event bubbles — it's the place to load the next step through HTMX, if it depends on what was filled in before.

document.addEventListener('tucano:change', (e) => {
  if (!e.target.matches('.tuc-stepper')) return;
  e.detail.value;      // step index
  e.detail.step;       // the indicator item
  e.detail.panel;      // the panel
  e.detail.instance;   // the Stepper
});

Keyboard and accessibility

The indicator is an ordered list: the screen reader announces "item 2 of 3" without anyone writing ARIA, and aria-current="step" says which one is current. On phones only the current step shows its name; the others' names are still there for the screen reader.

KeyAction
TabThe open step's fields and the buttons; hidden panels stay out of the way
EnterIn a text field, before the last step: Continue. On the last one, submits the form
Enter SpaceOn the buttons, the native click

When the step changes, focus goes to the new panel's title, and the next Tab reaches the first field. The title gets tabindex="-1" for that — focusable by the script, out of the Tab path.
