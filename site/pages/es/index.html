Componentes de formulario, listado y diálogo para quien escribe HTML.

Pon un atributo data-tuc-* en la plantilla y el campo se convierte en componente — sin React, sin paso de build y sin arrastrar un framework. Funciona con Django, Laravel, Rails o cualquier back-end que devuelva HTML, y con HTMX.

Instalación

Dos archivos y nada más. Elige el camino que encaje con tu proyecto — ninguno exige un paso de build de tu lado.

Fija siempre la versión. @latest se queda mucho tiempo en la caché de jsDelivr y sirve un build antiguo sin avisar.

Copia la carpeta dist/ a los archivos estáticos de tu proyecto. En Django:

{% load static %}



npm install tucano

import { DatePicker, Select, toast } from 'tucano';
import 'tucano/css';

Con npm tu empaquetador se queda solo con lo que importas: el date picker por sí solo es un tercio del paquete. Importar desde tucano no inicializa los campos solo — llama a Tucano.init(document) o importa tucano/auto.

Cómo funciona

El HTML que ya escribes sigue siendo el dueño del valor. El componente solo cambia el aspecto y añade el comportamiento.

1. Marca el campoUn atributo data-tuc-* en el <input> o el <select> de tu plantilla.
2. Se inicializa soloAl cargar la página y otra vez después de cada htmx:afterSwap — sin una línea de JavaScript.
3. El POST es el de siempreEl elemento nativo sigue en el formulario: name, required y los valores múltiples funcionan como siempre.

Fechas y números siguen el idioma de tu página

El date picker lee <html lang> para los nombres de los meses, los días de la semana y el formato de fecha, y las máscaras de moneda reciben un código de moneda. Las etiquetas, los placeholders y los mensajes son tuyos: escríbelos en tu plantilla, en cualquier idioma, como data-placeholder="Buscar clientes...".

Convive bien con el Tailwind de tu proyecto

El paquete no trae el preflight, y los componentes llevan su propio reset: tu CSS no rompe los componentes, y los componentes no tocan tu proyecto.
