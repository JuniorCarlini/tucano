Cómo usar

Solo el indicador, una etapa por página

Una <ol> con el nombre de cada etapa. La plantilla marca la actual con aria-current="step", que el lector de pantalla anuncia como "etapa actual", y las anteriores con is-done. No hay script: es el camino del SessionWizardView de django-formtools, o de cualquier asistente en que cada etapa es un POST.

    
  {% for step in wizard.steps.all %}
    
  1. 
      {{ step|title }}
    
    2. 
  {% endfor %}

Asistente en una sola página

El indicador, un .tuc-stepper__panel por etapa — con hidden a partir del segundo — y la barra de botones. Etapas y paneles se emparejan por orden. El título del panel (un <h2> a <h6>, o el <legend> de un <fieldset>) recibe el foco en cada cambio, y el lector de pantalla anuncia la etapa nueva.


  

    
    
      
  1. Datos
    2. 
      
  2. Dirección
    3. 
    

    

      Tus datos …
    

    

      Dirección …

Continuar valida los campos de la etapa con la validación del propio navegador — required, type="email", pattern, min — y no avanza si alguno falla: el campo recibe aria-invalid="true" y el aviso del navegador. Volver nunca valida. En la primera etapa Volver desaparece, y en la última Continuar da paso a Finalizar. El hidden de esos dos en la plantilla es lo que hace que la barra nazca bien antes del script.

Por qué es un único formulario

El panel oculto no sale del DOM, así que todo name va en el POST final, y el servidor recibe exactamente lo que recibiría de un formulario largo. No hay estado en JavaScript que sincronizar, y la validación del servidor sigue siendo la misma.

Enter en un campo de texto, antes de la última etapa, es Continuar. Sin eso enviaría el formulario, y el navegador bloquearía el envío por un campo obligatorio que la persona aún ni vio, sin decir cuál. Un reset en el formulario vuelve a la primera etapa.

Con Django, cuando el servidor devuelve un error

El formulario que vuelve del POST con error abre directo en la etapa del primer campo con aria-invalid="true" — que Django 5 escribe solo en todo campo que falló. Sin eso, el mensaje quedaría oculto dos etapas más adelante.


  Dirección
  {{ form.zip }}        {# con error, viene con aria-invalid="true": el asistente abre aquí #}
  {{ form.zip.errors }}

Para abrir en una etapa elegida, use data-start="2" (contando desde cero). Sin ella y sin error, vale la etapa marcada con aria-current="step", o la primera. data-validate="false" deja avanzar sin validar.

En JavaScript

const wizard = new Tucano.Stepper('#signup', {
  start: 0,          // etapa inicial
  validate: true,    // Continuar valida los campos de la etapa
  onChange: (index, { panel }) => console.log(index, panel),
});

wizard.next();                   // valida y avanza
wizard.prev();                   // vuelve, sin validar
wizard.go(2);                    // va directo, sin validar
wizard.go(0, { silent: true });  // sin disparar onChange
wizard.checkStep();              // true si los campos de la etapa pasan
wizard.index;                    // etapa abierta

Cada cambio dispara tucano:change en el elemento del asistente, y el evento burbujea — es el punto para cargar la etapa siguiente por HTMX, si depende de lo que se rellenó antes.

document.addEventListener('tucano:change', (e) => {
  if (!e.target.matches('.tuc-stepper')) return;
  e.detail.value;      // índice de la etapa
  e.detail.step;       // el ítem del indicador
  e.detail.panel;      // el panel
  e.detail.instance;   // el Stepper
});

Teclado y accesibilidad

El indicador es una lista ordenada: el lector de pantalla anuncia "elemento 2 de 3" sin que nadie escriba ARIA, y aria-current="step" dice cuál es la actual. En el móvil solo la etapa actual muestra el nombre; el de las demás sigue ahí para el lector de pantalla.

TeclaAcción
TabLos campos de la etapa abierta y los botones; los paneles ocultos quedan fuera del camino
EnterEn un campo de texto, antes de la última etapa: Continuar. En la última, envía el formulario
Enter EspacioEn los botones, el clic nativo

Al cambiar de etapa, el foco va al título del panel nuevo, y el siguiente Tab llega al primer campo. El título recibe tabindex="-1" para eso — enfocable por el script, fuera del camino del Tab.
