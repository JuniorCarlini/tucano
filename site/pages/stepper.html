Como usar

Só o indicador, uma etapa por página

Uma <ol> com o nome de cada etapa. O template marca a atual com aria-current="step", que o leitor de tela anuncia como "etapa atual", e as anteriores com is-done. Não há script: é o caminho do SessionWizardView do django-formtools, ou de qualquer assistente em que cada etapa é um POST.

    
  {% for step in wizard.steps.all %}
    
  1. 
      {{ step|title }}
    
    2. 
  {% endfor %}

Assistente numa página só

O indicador, um .tuc-stepper__panel por etapa — com hidden a partir do segundo — e a barra de botões. Etapas e painéis casam pela ordem. O título do painel (um <h2> a <h6>, ou o <legend> de um <fieldset>) recebe o foco a cada troca, e o leitor de tela anuncia a etapa nova.


  

    
    
      
  1. Dados
    2. 
      
  2. Endereço
    3. 
    

    

      Seus dados …
    

    

      Endereço …

Continuar confere os campos da etapa com a validação do próprio navegador — required, type="email", pattern, min — e não avança se algum reprovar: o campo ganha aria-invalid="true" e o aviso do navegador. Voltar nunca confere. Na primeira etapa o Voltar some, e na última o Continuar dá lugar ao Finalizar. O hidden desses dois no template é o que faz a barra nascer certa antes do script.

Por que é um formulário só

O painel escondido não sai do DOM, então todo name vai no POST final, e o servidor recebe exatamente o que receberia de um formulário comprido. Não existe estado em JavaScript para sincronizar, e a validação do servidor continua a mesma.

Enter num campo de texto, antes da última etapa, é Continuar. Sem isso ele enviaria o formulário, e o navegador barraria o envio por um campo obrigatório que a pessoa ainda nem viu, sem dizer qual. reset no formulário volta à primeira etapa.

Com Django, quando o servidor devolve erro

O formulário que volta do POST com erro abre direto na etapa do primeiro campo com aria-invalid="true" — que o Django 5 escreve sozinho em todo campo que reprovou. Sem isso, a mensagem ficaria escondida duas etapas adiante.


  Endereço
  {{ form.zip }}        {# com erro, vem com aria-invalid="true": o assistente abre aqui #}
  {{ form.zip.errors }}

Para abrir numa etapa escolhida, use data-start="2" (contando do zero). Sem ela e sem erro, vale a etapa marcada com aria-current="step", ou a primeira. data-validate="false" deixa avançar sem conferir.

Em JavaScript

const wizard = new Tucano.Stepper('#signup', {
  start: 0,          // etapa inicial
  validate: true,    // Continuar confere os campos da etapa
  onChange: (index, { panel }) => console.log(index, panel),
});

wizard.next();                   // confere e avança
wizard.prev();                   // volta, sem conferir
wizard.go(2);                    // vai direto, sem conferir
wizard.go(0, { silent: true });  // sem disparar onChange
wizard.checkStep();              // true se os campos da etapa passam
wizard.index;                    // etapa aberta

Cada troca dispara tucano:change no elemento do assistente, e o evento borbulha — é o ponto para carregar a etapa seguinte por HTMX, se ela depender do que foi preenchido antes.

document.addEventListener('tucano:change', (e) => {
  if (!e.target.matches('.tuc-stepper')) return;
  e.detail.value;      // índice da etapa
  e.detail.step;       // o item do indicador
  e.detail.panel;      // o painel
  e.detail.instance;   // o Stepper
});

Teclado e acessibilidade

O indicador é uma lista ordenada: o leitor de tela anuncia "item 2 de 3" sem ninguém escrever ARIA, e aria-current="step" diz qual é a atual. No celular só a etapa atual mostra o nome; o das outras continua lá para o leitor de tela.

TeclaAção
TabOs campos da etapa aberta e os botões; os painéis escondidos ficam fora do caminho
EnterNum campo de texto, antes da última etapa: Continuar. Na última, envia o formulário
Enter EspaçoNos botões, o clique nativo

Ao trocar de etapa, o foco vai ao título do painel novo, e o próximo Tab chega ao primeiro campo. O título ganha tabindex="-1" para isso — focável pelo script, fora do caminho do Tab.
